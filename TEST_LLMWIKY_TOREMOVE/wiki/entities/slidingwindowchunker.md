# SlidingWindowChunker

## Summary
The `SlidingWindowChunker` splits text into overlapping chunks using a fixed-size sliding window. It approximates tokens at 4 characters each for fast character‑level processing, configures window size via `maxTokens` and overlap via `overlap`, and snaps chunk boundaries to word spaces to avoid mid‑word cuts. This implementation is intentionally allocation‑efficient, performing all indexing on the original string and creating substrings only at chunk creation.

## Key Details
- Class: `SlidingWindowChunker` in namespace `AGXIOME.Storage.Chunkers`.
- Implements `IChunker` with `ChunkerType = ChunkerType.SlidingWindow`.
- Method: `IReadOnlyList<DocumentChunk> Chunk(string text, int maxTokens = 512, int overlap = 64)`.
- Token approximation: 1 token ≈ 4 characters; all lengths and steps operate at character level.
- Step size in characters = `(maxTokens - overlap) * 4`, with a minimum of 1.
- If the entire text fits within the first window, a single chunk containing the whole text is returned.
- For texts longer than the window, chunks are generated by sliding the window by the step size.
- After sliding, each chunk attempts to snap its end to the last space character (`' '`) to avoid splitting words. If no space is found, the original end is used.
- Empty or whitespace‑only segments are skipped; if no valid chunks are produced, a single chunk of the original text is returned.
- Each chunk is a `DocumentChunk` containing the extracted substring, an index, and start/end character positions.
- Allocation‑efficient: no intermediate copies until `DocumentChunk` construction.
